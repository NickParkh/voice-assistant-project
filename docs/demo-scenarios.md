# Демонстрационные сценарии (Лабораторная работа №4)

В данном документе описаны сценарии проверки работоспособности микросервисной системы голосового ассистента.

## 1. Успешный сквозной сценарий
**Цель:** Проверить цепочку синхронных вызовов (Оркестратор -> ASR -> NLU -> Skill -> TTS) и асинхронную публикацию события.

**Входные данные (запрос в `dialog-orchestrator`):**

- `Key-Idempotency`: 123e4567-e89b-12d3-a456-426614174000 (можно использовать другой, главное в правильном формате)
- `sessionId`: "123"
- `audioUri`: "s3://voice-ai-audio/2026-10-01/user42.wav"
- `isOnline`: true

**Ход выполнения:**
1. Оркестратор получает запрос и вызывает `asr-service` (синхронно).
2. `asr-service` распознает текст ("Открой браузер") и публикует событие `speech.recognized` в in-memory очередь (асинхронно).
3. Оркестратор передает текст в `nlu-service` (синхронно).
4. `nlu-service` возвращает намерение `open_browser`.
5. Оркестратор вызывает `skill-service` для выполнения навыка (синхронно).
6. `skill-service` имитирует открытие браузера и сохраняет запись в in-memory БД.
7. Оркестратор вызывает `tts-service` для синтеза ответа (синхронно).
8. Пользователь получает ответ с кодом `200 OK`.

**Ожидаемый результат:** 
- В Swagger приходит JSON с распознанным текстом и статусом `EXECUTED`.
- В терминале `asr-service` появляется лог `[EVENT WORKER] Получено событие: speech.recognized`.
- В терминале `skill-service` появляется лог `>>> ОС: Открываю браузер...`.

## 2. Сценарий со сбоем и компенсацией (Сага)
**Цель:** Проверить обработку ошибки на шаге распознавания речи и возврат единой модели ошибок (RFC 7807).

**Входные данные (запрос в `dialog-orchestrator`):**
- `sessionId`: "456"
- `audioUri`: "s3://voice-ai-audio/2026-10-01/unknown_noise.wav" (файл с шумом, который ASR не может распознать).

**Ход выполнения:**
1. Оркестратор вызывает `asr-service`.
2. `asr-service` не находит нужный файл и возвращает ошибку `422 Unprocessable Entity`.
3. Оркестратор перехватывает ошибку (блок `try/except`) и прерывает цепочку (NLU, Skill и TTS **не вызываются**).
4. Оркестратор возвращает клиенту ответ в формате RFC 7807 (application/problem+json).

**Ожидаемый результат:** 
- В Swagger приходит ответ `422` с телом:

  }
